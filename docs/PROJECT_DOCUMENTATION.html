1. Project Overview

A personal portfolio website for Muhamed Ahmed Shifaw, Software Developer. Originally a static HTML site, it was rebuilt as a modern full-stack application with the same visual design plus a complete admin content-management system.

Key capabilities

  • Public portfolio — Home, About, Experience, Projects, Skills, CV, and Contact pages, all rendered from live database content (no code changes or rebuilds needed for content updates).
  • Admin dashboard (/admin) — password-protected panel where the owner edits every section of the site: About (including photo upload), Experience, Projects, Skills, CV/Resume (including PDF upload), Contact, and theme colors.
  • Database-backed content — every text section lives in PostgreSQL. Public pages read the database on every request, so admin edits appear site-wide instantly.
  • File uploads via Vercel Blob — profile photos and CV PDFs upload to Vercel's Blob CDN; the public URL is persisted to the database automatically within the same upload request.
  • Theme colors — primary and background colors editable in admin, applied via CSS custom properties.
  • Dark/light mode — with a pre-hydration script to avoid flash-of-wrong-theme and React hydration mismatch.

4. Database Schema (Prisma models)

Single-row sections (fixed id = 1)

List sections (ordered; the order field is unique)

ModelFields
Projecttitle, desc, role, tech (string array)
Experiencetitle, company, location, date, responsibilities (string array)
Skillname
CvStatlabel, number (belongs to Cv)
CvEducationdegree, institution, date (belongs to Cv)
CvLanguagelanguage, level (belongs to Cv)

lib/db.ts assembles these rows into the single Content object the UI consumes (getContent()); saveContent(partial) patches only the sections present in the request — list sections sync atomically inside a transaction (delete-missing, upsert-rest). If the database is unreachable, a 30-second circuit breaker serves seeded defaults instead of erroring, keeping the public site online.

5. Admin Panel Guide

Log in at /admin with the ADMIN_PASSWORD value. Sections (left sidebar tabs):

  1. About Me — name, title, bio, location; Profile Photo widget (Choose File → Upload & Save; uploads to Blob and updates the site immediately; persisting a blob: preview URL is blocked by a guard).
  2. Experience — job list with add/remove, per-job responsibilities; Save Experience.
  3. Projects — add/remove/edit projects (title, description, role, tech list); Save Projects.
  4. Skills — comma-separated skill list; Save Skills.
  5. CV / Resume — PDF upload (same Blob flow), profile bio, stats, education, languages; Save CV.
  6. Contact — email, phone, GitHub, LinkedIn, Twitter/X, Telegram; Save Contact.
  7. Colors — primary and background color pickers; Apply Colors.
  8. Account & Security — change password (verifies the current password; minimum 8 characters). The new value is stored in the Vercel project's ADMIN_PASSWORD env var via the Vercel REST API; it takes effect on the next deployment because serverless functions snapshot env vars at deploy time.

All saves go through PUT /api/content (or the upload routes), which requires a valid admin session cookie.

6. Authentication & Security

  • Session: after login, an HMAC-SHA256–signed token (payload = expiry, 7-day TTL) is set as an httpOnly, sameSite=lax, secure-in-production cookie named admin_session. Verification is timing-safe.
  • Secrets: AUTH_SECRET signs tokens; ADMIN_PASSWORD gates login. Production values live in Vercel project settings, never in the repo (.env* is git-ignored).
  • Dev defaults: insecure fallbacks (admin123, dev secret) warn loudly but exist only outside production.
  • Password change: authenticated-only; verifies the current password before accepting a new one.
  • Public API: GET /api/content exposes read-only public data; all writes are session-guarded.
Known hardening opportunities (not yet implemented): login rate limiting; moving the password into the database as a bcrypt hash so changes take effect instantly.

8. Production Deployment (current state)

  • Project: muhamed-portfolio, linked via .vercel/project.json.
  • Database: Neon Postgres connected through Vercel's Storage integration; DATABASE_URL and POSTGRES_* vars injected automatically for all environments. Initial migration deployed; content seeded from data/content.json.
  • Blob store: portfolio-blob (store_Edvho7f7UGv0Sa3X, public access, region iad1), OIDC-connected. Verified end-to-end in production: photo and PDF uploads return Blob URLs that are publicly served and persisted to the database.
  • Domain: clean production alias https://muhamed-ahmed-portfolio.vercel.app. Vercel auto-appends the account name to raw deployment URLs; the alias hides it. Deployment protection is disabled because the admin area has its own authentication.
  • Images: next.config.ts allows *.public.blob.vercel-storage.com in images.remotePatterns — without this, Next's image optimizer returns 400 for Blob photos and the UI falls back to initials.
  • Build: prisma generate && next build; all DB-reading pages are force-dynamic, so builds never touch the database.

Redeploying: npx vercel --prod (or push to the connected Git repo). After changing the admin password through the panel, redeploy for it to take effect.

Useful commands: npm run db:studio (browse data), npm run db:migrate, npm run db:push, npm run lint, npx tsc --noEmit (typecheck).

No local Postgres? The site still renders — lib/db.ts falls back to seeded defaults via the circuit breaker; only admin saves require a reachable database.

11. Suggested Next Steps

  3. Custom domain — attach a purchased domain in Vercel project settings.
  4. Analytics — Vercel Analytics or a lightweight page-view counter.
